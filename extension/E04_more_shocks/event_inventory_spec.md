# E4 event inventory specification (frozen before CSV outcome inspection)

Scope: official Cboe VXN, RVX, OVX, GVZ daily histories retrieved for this stage. Other named sources receive availability/terms status only until an official history and rights can be verified. No model fitting. Retrieval filenames and SHA-256 values are recorded separately.

For each index, parse the official CSV date and closing index level, require unique sorted dates and finite positive closes, and retain its own trading-session calendar. Record exclusions without forward filling. Freeze the source snapshot as fetched; do not refresh during this inventory.

At each valid session t, candidate onset if log(V_t/V_(t-1)) >= log(1+7/20) OR log(V_t/V_(t-5)) >= log(1+10/20), only when all required prior sessions are valid and consecutive within that source's observed exchange-session rows. Accept candidate if >30 calendar days after last accepted onset. Count candidate triggers and accepted onsets separately. No future peak, named-crisis merge, or threshold tuning.

An accepted onset is potentially eligible only with 250 valid pre-onset sessions and a full onset-through-119th subsequent observed session panel (120 sessions total), a complete onset-through-10th session peak-search window, and a strictly positive 250-session arithmetic pre-onset baseline. Exclude if another accepted onset occurs before panel end; report this separately. Descriptive peak anchor is max over onset..+10, matching E5's planned definition, but do not fit any curve here. Full E5 usable status remains unverified because normalization, anchor, terms and cross-source comparability require independent validation.

For every accepted onset construct the calendar-date interval from onset through its 119th following session where available, else a right-censored interval ending at source cutoff. For potentially eligible onsets use complete intervals. Across sources, connect events whose complete calendar-date intervals intersect (inclusive); take transitive components. Report raw onset coincidences and pairwise interval overlaps by index pair, component IDs, component member counts and distinct source-index counts. A component is a dependence unit for this inventory, not an independent statistical observation guarantee. Retain events individually in a dated catalog. Baseline and future windows are not silently pooled into the onset-through-119 overlap measure; full E5 data-use footprints need separate clustering if E5 occurs.

Numerical outputs: event_catalog.csv, overlap_matrix.csv, clusters.csv, achievable_counts.csv, number_ledger.csv. All counts are preliminary until Vera verifies. Code must be saved with hash before it reads the histories. This specification is review-informed by the accepted E2/E3 reports and E4/E5 briefs, not blinded preregistration.
